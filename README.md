# 圆桌 · 本地多模型 AI 聊天室

原生 HTML、CSS、JavaScript 前端 + Node.js 本地代理。支持 OpenAI 兼容 API，以及通过官方 Codex SDK 使用 ChatGPT 订阅额度。没有模拟回复、应用账户或外部数据库。所有 Markdown 依赖从本地加载，页面不依赖 CDN。

## 功能

- 邀请多位 AI，用独立角色围绕同一话题轮流讨论；你可以随时加入。
- 支持 OpenAI 兼容 API、Ollama 等本地服务，以及 ChatGPT 订阅的 Codex 额度。
- 每位 AI 独立设置模型、思考程度与流式输出；讨论可暂停、继续、重试和追加轮数。
- 会话保存在自己的浏览器，支持 JSON 备份和文本导出。

## 下载与启动

这是一个供每个人在自己电脑运行的项目。每位使用者配置自己的 API Key 或登录自己的 ChatGPT 账号，聊天记录和凭证不会通过 GitHub 分享。

### 1. 准备环境

安装 [Node.js](https://nodejs.org/) **22 或更新版本**（包含 npm），安装后重新打开终端。浏览器使用新版 Edge、Chrome 或 Firefox。

### 2. 下载项目

打开 [GitHub 仓库](https://github.com/HTTm1saka/ai-roundtable)，点击 **Code → Download ZIP**，把 ZIP 完整解压到自己的文件夹。不要在压缩包内部启动。无需安装 Git。

也可以用 Git 下载：

```sh
git clone https://github.com/HTTm1saka/ai-roundtable.git
cd ai-roundtable
```

### 3. 启动

**Windows：** 双击解压目录里的 **start.cmd**。如果提示找不到 Node.js，安装 Node.js 后重新打开文件夹或终端再试。这个入口不运行 PowerShell 脚本，无需调整执行策略。

**macOS / Linux：** 在解压目录打开终端，执行：

```sh
sh start.sh
```

**所有平台也可以使用：** 在项目目录运行：

```sh
node scripts/launch.js start
```

启动器会检查 Node.js、运行依赖和当前系统的 Codex 二进制文件；首次运行、依赖缺失或版本变化时自动安装。首次安装需要网络，等待终端显示启动成功后，用浏览器打开 **http://127.0.0.1:3210**。保持终端运行；停止服务按 **Ctrl+C**。每次使用都从同一入口启动。

熟悉 npm 的使用者也可手动安装启动：

```sh
npm ci --omit=dev --include=optional
npm start
```

Windows PowerShell 若拦截 npm.ps1，使用 npm.cmd 替代 npm，例如 `npm.cmd start`；或直接用 start.cmd。无需以管理员身份启动本项目。

### 4. 配置并开始讨论

1. 在页面右侧“参与 AI”中点击“编辑”，选择接入方式。
2. API 模式填写自己的 Base URL、Key 和模型 ID；订阅模式按下文完成 ChatGPT 登录。
3. 选择思考程度，点击“测试连接”验收后保存。测试会使用实际额度。
4. 输入话题，设置计划轮数，点击“开始讨论”。

不要双击 index.html 或以 file:// 打开页面。界面本身可在安装依赖后离线加载，调用远程 AI 仍需要网络。

### 端口与数据位置

端口被占用时，在项目目录选择另一个端口：

Windows PowerShell：

```powershell
$env:PORT = "3212"
node scripts/launch.js start
```

macOS / Linux：

```sh
PORT=3212 sh start.sh
```

然后打开 http://127.0.0.1:3212。服务只绑定本机 127.0.0.1，每位使用者各自运行；手机或其他电脑不能通过这个地址访问你的实例。

**请始终使用相同的浏览器资料、地址和端口。** localhost 与 127.0.0.1、3210 与 3212 分别拥有独立的网站存储；换地址不会删除原记录，但原记录不会出现在新地址中。页面限制同一浏览器来源只允许一个可写标签页，避免数据相互覆盖。

## API 配置示例

### 使用 ChatGPT 订阅额度

Windows 可直接双击项目中的 **login-chatgpt.cmd**，按提示登录。所有平台也可以在项目目录运行（首次使用会自动检查并安装依赖）：

```sh
node scripts/launch.js login
```

已经安装依赖时，也可以执行：

```powershell
npm run login:chatgpt
```

按终端提示在浏览器完成 ChatGPT 登录。然后在参与者的“编辑”中，把“接入方式”改为 **ChatGPT 订阅（通过 Codex）**，点击“检查登录状态”。模型名称可以留空使用 Codex 默认模型，也可以填写该订阅实际可用的 Codex 模型 ID。保存后即可测试连接或开始讨论；同一讨论可以混用订阅参与者和 API 参与者。

此模式使用 ChatGPT 套餐包含的 **Codex 额度**，是否可用及具体限制由账户套餐决定，不是把网页聊天次数转换为 API 余额。“测试连接”也会消耗额度。登录失效、额度不足或模型不可用时会暂停，**不会自动改用付费 API Key**。现有 API 模式保持独立。依据：[官方认证说明](https://learn.chatgpt.com/docs/auth)、[Codex SDK](https://learn.chatgpt.com/docs/codex-sdk)。此集成用于本机个人运行。

登录信息由 Codex 保存在用户目录的 `.ai-roundtable/codex/` 中，与日常使用的 `.codex/` 分开；已有 Codex 登录不会自动共享。凭证不发送到浏览器、不进入 IndexedDB 或 JSON 备份。Codex 运行记录也可能保存在该目录，包含发送的讨论上下文；清除浏览器数据不会删除这些文件。请把这个目录视为私人数据。退出项目订阅登录可运行：

```powershell
npm run logout:chatgpt
```

每次发言创建独立 Codex thread，并传入应用裁剪后的完整角色及讨论上下文。禁用 shell、浏览器、应用插件和多代理等工具，使用只读沙箱。流式更新以 Codex 消息事件为单位，不保证逐 token 显示。安装时须保留 npm 可选依赖，以便安装当前操作系统的 Codex 二进制文件。

### 使用 API Key

点击每个参与者的“编辑”，独立填写名称、角色、Base URL、Key 和模型名称。可以增加、移除和调整顺序。修改后的参与者配置也是以后新建会话的默认配置；已有会话保留自己的配置。

| 服务 | API Base URL 示例 | 模型名称 | API Key |
|---|---|---|---|
| OpenAI | `https://api.openai.com/v1` | 填写账户实际可用、支持 Chat Completions 的模型 ID | 服务商 API Key |
| 其他兼容服务 | `https://你的服务商域名/v1` 或服务商指定的 API 根路径 | 对应服务商提供的准确模型 ID | 对应服务商 Key |
| 本地 Ollama 的兼容接口 | `http://127.0.0.1:11434/v1` | 本机已下载的模型名称 | 通常可留空 |
| 本地其他 OpenAI 兼容服务 | 如 `http://127.0.0.1:1234/v1`，以实际服务设置为准 | 已加载模型的 ID | 以本地服务要求为准 |

不会自动猜测 `/v1`：填写 `https://host/v1` 时请求 `https://host/v1/chat/completions`；填写 `https://host/custom/api` 时请求 `https://host/custom/api/chat/completions`。也接受完整 `…/chat/completions`，尾部斜线会去除，不会重复拼接。URL 不允许包含用户名、密码、查询参数或片段。Key 单独以 `Authorization: Bearer …` 传递。

接口依据 [OpenAI Chat Completions 文档](https://developers.openai.com/api/reference/resources/chat)。请求发送 `model`、`messages`、`stream`，显式选择思考程度时另外发送 `reasoning_effort`，消息角色限定为 `system`、`user`、`assistant`。服务商必须提供这一兼容协议；原生 Anthropic Messages、Gemini 原生接口或仅支持 Responses 的模型需要另配兼容网关，不能直接填它们的原生地址。

“测试连接”会发起真实请求并检验文本响应，可能产生少量费用。测试不写入聊天，也不计入轮数。不预设会过时的付费模型 ID，请从服务商控制台选择。API Key 不是 ChatGPT 网页登录凭证。

## 思考程度

每位参与者的“编辑”窗口提供“思考程度”选择，API 和 ChatGPT 订阅均可独立设置。共用档位包括跟随模型（默认）、极低、低、中、高、超高和最高；API 还可选择关闭思考，订阅还可选择极致。参与者卡片显示非默认档位。设置随会话与备份保存，旧配置沿用模型默认值。

“跟随模型”不发送额外推理参数；API 显式选择通过 reasoning_effort 发送，订阅通过 Codex SDK 的 modelReasoningEffort 传入。实际可用档位取决于模型和服务商，选择不支持的档位可能被拒绝或忽略。不兼容时改回“跟随模型”后手动重试，应用不会自动重复请求。更高程度通常耗时更久、消耗更多额度。讨论期间先暂停并等待当前回复结束，再编辑参与者；之后的请求使用新设置。切换接入方式时，不兼容的档位恢复为默认。

## 使用流程与讨论语义

1. 编辑默认“探索者”“审思者”，填写真实配置并测试。AI 数量可自定义，应用上限 100 位。
2. 输入话题并发送，设置计划轮数，点击“开始讨论”。也可以直接填写输入框后点击开始，它会先保存话题。
3. 按参与者顺序发言，每轮中每位 AI 完整成功发言一次后进入下一轮，达到计划轮数自动结束。顶部显示本轮序号、总轮数、已完成轮数及正在发言者。
4. 随时发送人类消息，消息立即加入记录并保存。当前 AI 请求不会被重发；下一位 AI 的请求读取更新后的全部有效上下文。人类发言不重置或增加轮数。
5. “暂停”允许当前回复完成，不再发起下一次请求。在暂停完成前配置仍锁定。“继续”从未处理的 AI 接着运行。
6. “停止”取消当前请求与后续调用，部分回复标为中断，不计成功发言；之后可以继续，让同一位 AI 重新完整回答。
7. 请求失败自动暂停，不无限重试。可以“重试当前 AI”，或“跳过并继续”。跳过有独立事件记录，不计为成功发言，但该位本轮已处理，其他 AI 完成本轮后正常进入下一轮。
8. 结束后发消息只会保存，不调用 API。设置“追加轮数”并点击“追加并继续”，总轮数增加，顺序继续。

暂停或停止完成后可以修改参与者与顺序。本轮已成功/跳过者不会重复发言；未处理者按新顺序，新增者参与本轮，删除者退出本轮；下一轮采用最新完整列表。没有进行中的轮次时，编辑配置不会提前开启一轮。

同一会话只有一个生成任务，开始/继续/重试的重复点击不会并发启动。允许切换会话，旧任务仍只写原会话；也允许另一个会话开始自己的独立讨论。正在生成的会话不能删除。删除会话必须确认。

## 上下文、流式与消息

- 每位 AI 使用自己的 system 角色提示词。自己的历史成功回复转换成 assistant，其他 AI 和人类转换成 user，并明确标记类型、名称。提示模型把其他参与者发言视为讨论内容。
- 默认上下文上限 24,000 **字符**，可调整到 1,000–1,000,000 字符。这是可移植的字符估算，不是精确 token 计数；需留出模型输出余量，实际服务商上下文超限仍会报错暂停。
- 裁剪始终保留完整话题和当前角色提示词，从新到旧保留消息；边界消息保留尾部，省略更旧消息，同时页面提示。话题与角色本身超限则暂停，要求增大上限或缩短配置。失败、中断、跳过事件不作为完整模型发言输入。
- 默认 SSE 流式显示，支持跨网络分片 UTF-8、CRLF、多行 data 和 `[DONE]`。服务商直接返回 JSON 时也可读取；若不支持 `stream:true`，关闭该 AI 的流式选项后**手动**重试，不会自动重复付费请求。
- 无终止标记的断流、输出 length/content_filter/tool_calls 或空文本视为未完整成功，保留部分文本并暂停。流结束后 `stop` 或 `[DONE]` 视为完整。
- Markdown 通过本地 marked + DOMPurify 白名单渲染。禁用消息脚本、样式、嵌入、图片及危险链接；支持代码块、列表、表格与复制。内容中的 HTML 脚本不会执行。
- 用户在底部时跟随增量滚动；阅读历史时保留位置，可点击“回到最新消息”。

## 本地数据、密钥与备份

使用浏览器 **IndexedDB**（数据库 `local-ai-roundtable`，对象存储 `app`）保存会话、模型配置、消息时间、发言人、顺序、轮次与游标。无注册表操作、无数据库安装。API 模式的 Node 代理不写聊天或密钥到文件，不打印请求、Key 或上游原始错误。订阅模式另有上文说明的 Codex 本地凭证与运行记录。

API Key 默认“仅本次使用”，只在此页面内存中使用，所有持久化路径会过滤它；刷新关闭后需要重新输入。选择“记住到本地”才保存至 IndexedDB。**本地保存不是加密保险库：可访问浏览器资料的人及此页面脚本可能读取记住的密钥。** 同一密钥仅发送给你为该 AI 配置的地址。

新消息立即保存，流式部分回复约每 700ms 保存一次，完成/失败/停止再保存。突然关闭或断电可能丢失最后一小段尚未提交的增量。成功发言推进游标和消息状态作为同一数据快照提交。重新打开后恢复记录，将未完成生成标为“已中断”，但**绝不自动恢复 API 调用**。刷新中断后可重试或跳过；已完成记录无需重跑。

左侧“导出备份”导出所有会话和默认配置为 JSON；**始终排除配置中的 API Key，即使选择了记住**。密钥字段留空。若你主动把密钥写进普通聊天或提示词，那属于原文内容，不会按语义自动识别删除，请勿这样使用。

“导入备份”限制 50 MB，先检查版本、字段、消息状态、数值范围与 ID，一旦发现格式无效整个导入拒绝。合法数据分配新的会话、消息与参与者 ID，并追加“（导入）”，不会覆盖原会话。导入时忽略所有 Key，不启动讨论。右上“导出文本”仅导出当前会话，含时间、身份和完整/失败/中断等状态。

读取失败会显示阻断提示，不伪装成“没有记录”，也不会初始化空记录覆盖；写入失败提示导出并暂停后续自动生成。导出操作依赖内存，保存失败时仍可导出。清除网站数据、删除浏览器资料、隐私窗口关闭可能删除记录，建议定期备份。

## 异常处理

| 现象 | 行为及处理 |
|---|---|
| 401 / 403 | 显示认证或权限失败，检查 Key、权限及额度 |
| 404 | 检查模型 ID、Base URL 和版本路径 |
| 429 | 限流或额度不足，自动暂停，稍后手动重试 |
| 400 / 422 | 协议或参数不兼容，检查 Chat Completions、system 和流式支持 |
| 返回网页 / HTML | 提示检查是否把网站首页当成 API 地址 |
| 网络故障 / DNS / TLS | 暂停并保留部分回复，检查 Node 可访问的网络 |
| 超时 | 默认 120 秒，可设置 5–600 秒；中断请求并暂停 |
| 本地服务关闭 | 提示无法连接代理，重新执行 npm start |
| 浏览器跨域 | 同源请求本地代理，由 Node 请求服务商，无需服务商配置浏览器 CORS |

代理拒绝外站 Origin、异常 Host、无应用请求标记的调用，以及重定向；不会将 Key 随重定向发往其他站点。不返回服务商原始错误文本，避免上游回显密钥。服务只用于本机个人运行，未配置远程用户认证。
